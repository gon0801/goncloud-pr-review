## Qué cambió

- `review_domain.py`: tipos nuevos `WorkRequest` (id numérico monotónico + `legacy_id` + origen/generación/estado), `RunKey`, `Receipt`, `StorageBudget`, `EncodedCheckpoint`, `ReviewTarget`, cobertura discriminada (`CompleteClaim`/`Partial`/`UnknownCoverage`); `Snapshot` gana `request_count` y `receipts`; `ReviewPolicy` gana `schema_version` y `diff_mode`; `ReviewPlan.delivered`; `ValidatedReport.coverage`.
- Validación schema 3 (`_v3_snapshot`) sobre la base común extraída (`_base_snapshot`): contadores, revisión, findings y descartes ≤ cursor idénticos a v2; `request_count`/ids 1..N únicos; `legacy_id` no vacío y sin duplicados; receipts con command_id 1..cursor únicos y effect no vacío; referencias a hallazgos existentes.
- `read_snapshot` reconoce schema 3 → `Valid`; schema ≥ 4 sigue `Future`; corrupto → `Invalid` (nunca vacío).
- `encode_snapshot(snapshot, budget=None)`: legado/v2 siguen devolviendo `str` (llamadores existentes intactos); v3 devuelve `EncodedCheckpoint` (bloque + schema + bytes reales UTF-8) o `CapacityExceeded`. El escape `-->`/`--!>` → `--\u003e`/`--!\u003e` es REVERSIBLE (json.loads restaura los originales) y sustituye la sustitución con pérdida `--›` que v2 mantiene para atrás-compatibilidad; los campos v3 viajan crudos (identidad preservada).
- `snapshot_a_v3`: migración idempotente v1/v2 → v3; solicitudes de texto reciben ids numéricos 1..N y guardan su identificador anterior (`legacy_id` persistido en cada solicitud), sin compactar pendientes.
- `accept_report` acepta schema 2 y 3 (legado sigue `Keep`); `Replace` conserva schema, request_count, receipts y pendientes, y avanza generación.
- `normalize_policy(boot)`: identidad externa `current`/`anchors` (el valor interno antiguo `titles` se adapta en esta frontera), modos full/incremental, schema_version 2/3, presupuestos validados, exclusiones como tupla de patrones.
- `review.py` (build_findings): el motivo del Keep de memoria válida ya no fija "schema 2" (usa `schema {load.snapshot.schema}`); cmd_publish solo comentario actualizado. Emisión schema 3 DESACTIVADA: producción sigue emitiendo legado/v2 (`serialize_findings`); v3 solo se emite si el Snapshot ya es schema 3.
